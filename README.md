# Лабораторная работа №3 - интерпретируемая модель отбора резюме и поддержки найма

Программная реализация на Go без сторонних библиотек. Проект продолжает продукционную модель из ЛР №1: критерии опыта, технического теста, soft skills и этики/безопасности. Дополнительно реализован отдельный модуль маршрутизации резюме по профессиональным категориям на основе интерпретируемых ключевых слов.

## Что делает программа

1. **Классификация резюме.** Нормализует текст, подсчитывает совпадения с ключевыми словами категорий и возвращает категорию, список совпадений, оценку и кандидата на второе место. Оценка совпадений - это не вероятность.
2. **Система продукционных правил.** Принимает четыре признака кандидата, применяет правила в заданном порядке, выдаёт `OFFER`/`REJECT`, код сработавшего правила и объяснение.
3. **Эксперименты.** Оценивает модуль классификации по CSV с колонками `Category,Resume`, удаляя повторы текста; выполняет анализ чувствительности к порогам технического теста и soft skills; записывает результаты в CSV.
4. **Автотесты.** Проверяют правила отбора, безусловный этический запрет и работу классификатора.

## Требования

- Go 1.21 или новее.
- Сторонние зависимости не нужны.

## Быстрый запуск

Из корня проекта:

```bash
go test ./...
go run . -mode demo
```

Классифицировать резюме:

```bash
go run . -mode classify -text "Python Django DRF MySQL RESTful web services Github"
```

Принять решение по JSON-файлу:

```bash
go run . -mode decision -input examples/candidate_offer.json
# изменить пороги:
go run . -mode decision -input examples/candidate_offer.json -tech 75 -soft 65
```

Провести тест на включённой компактной выборке:

```bash
go run . -mode eval -dataset testdata/resume_benchmark.csv
```

Провести эксперимент с параметрами и записать таблицу:

```bash
go run . -mode sweep -out results/parameter_sweep.csv
```

## Проверка на полном публичном наборе резюме

Источник - `UpdatedResumeDataSet.csv`, публично размещённый в репозитории [Automated Resume Screening](https://github.com/aniketnandi/automated-resume-screening). В описании источника указаны 962 строки, 25 категорий и 166 уникальных текстов резюме; в наборе есть повторы.

Скачать полный CSV в каталог `data`:

**Windows PowerShell**
```powershell
.\scripts\download_dataset.ps1
go run . -mode eval -dataset data/UpdatedResumeDataSet.csv
```

**Linux/macOS**
```bash
./scripts/download_dataset.sh
go run . -mode eval -dataset data/UpdatedResumeDataSet.csv
```

Программа устраняет точные повторы текста перед расчётом метрик. Поскольку опубликованный набор содержит категории резюме, а не реальные решения о найме, он подходит для проверки маршрутизации резюме по профессиональным профилям, но **не** для расчёта точности решения «нанять/отказать».

Компактный `testdata/resume_benchmark.csv` содержит 25 синтетических коротких примеров - по одному на категорию, составленных по типичным ключевым словам соответствующих профессий. Это не буквальная выборка строк из оригинального CSV, а smoke-test для проверки программного конвейера; метрики по нему нельзя интерпретировать как качество на реальном рынке труда. Для полноценной оценки используйте исходный CSV и отдельную экспертно размеченную тестовую выборку.

## Параметры модели

- `-tech`: минимальный балл технического теста, по умолчанию 70 из 100.
- `-soft`: минимальный балл soft skills, по умолчанию 60 из 100.

Эти числовые пороги являются явной операционализацией бинарных признаков «тест высокий/низкий» и «soft skills хорошие/слабые» из первой лабораторной работы. Их можно менять из командной строки.

## Ограничения

- Классификация строится на словаре вручную заданных ключевых слов; синонимы, разные языки и контекст могут приводить к ошибкам.
- Число совпадений не является вероятностью пригодности кандидата.
- Система не обучается на исходах реального найма: опубликованный датасет содержит метки профессиональных категорий.
- Оценки soft skills и этики/безопасности должны поступать из стандартизованных процедур, а не из автоматического анализа лица, эмоций или защищённых персональных характеристик.
- ПО - учебный прототип для поддержки решения, а не готовая система кадрового отбора. Финальное решение должен проверять человек.

## Состав проекта

- `main.go` - CLI и режимы запуска.
- `classifier.go` - классификатор резюме на базе правил ключевых слов.
- `decision.go` - продукционная модель решения о найме.
- `experiments.go` - расчёт метрик и исследование чувствительности параметров.
- `rules_test.go` - автоматические тесты.
- `testdata/resume_benchmark.csv` - компактная внешняя smoke-test выборка.
- `examples/` - образцы входа для кандидата.
- `scripts/` - загрузка полного публичного датасета.
- `results/parameter_sweep.csv` - результаты анализа чувствительности.
